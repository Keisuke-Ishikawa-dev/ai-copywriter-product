# AI помощник для подготовки товарных описаний

Это прототип сервиса для B2B каталога контрольно измерительных приборов. На вход он принимает JSON с названием товара, производителем, характеристиками и исходным описанием. На выходе формирует SEO заголовок, SEO описание, характеристики, поисковые запросы и короткий commercial блок для менеджера.

Сервис сделан так, чтобы технические значения не появлялись из воздуха. LLM получает строгую инструкцию, а результат дополнительно проходит детерминированную проверку. Если данных недостаточно, модель должна написать «данных нет», добавить поле в missing_data и сформировать вопрос менеджеру.

## Запуск без API ключа

Создать окружение и установить зависимости.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Запустить демонстрационный режим.

```bash
python app.py --input examples/products.json --output examples/results.json --demo
```

Демонстрационный режим нужен для быстрой проверки интерфейса и формата результата. Он не обращается к LLM API.

## Запуск с LLM API

Скопировать `.env.example` в `.env` и указать ключ.

```bash
cp .env.example .env
```

После этого можно выполнить.

```bash
python app.py --input examples/products.json --output output.json
```

По умолчанию используется OpenAI и модель из переменной `OPENAI_MODEL`. Через `OPENAI_BASE_URL` можно подключить совместимый endpoint, например локальный шлюз или корпоративный прокси.

## HTTP интерфейс

Запуск сервера.

```bash
uvicorn app:app --reload
```

Проверка здоровья.

```bash
curl http://127.0.0.1:8000/health
```

Генерация карточки.

```bash
curl -X POST http://127.0.0.1:8000/generate \\
  -H 'Content-Type: application/json' \\
  -d '{"name":"Манометр показывающий DM 02","manufacturer":"Манотомь","specs":{"диапазон измерений":"0–1,6 МПа","класс точности":"1,5","присоединение":"G1/2"},"description":"Прибор для измерения избыточного давления.","demo":true}'
```

## Что находится в репозитории

`app.py` содержит CLI, HTTP endpoint, промпт, вызов LLM и проверку результата.

`prompt.txt` содержит полный системный промпт, который можно менять отдельно от кода.

`order_schema.json` описывает ожидаемую структуру ответа.

`validate_order.py` выполняет независимую проверку JSON.

`examples/products.json` содержит два демонстрационных товара.

`examples/results.json` содержит пример результата для двух товаров.

## Принятые решения

Я выбрал JSON как основной формат обмена. Он удобнее для интеграции с CMS, CRM и последующей проверки, чем свободный текст. Для контент менеджера этот JSON можно отобразить в таблицу или использовать в шаблоне карточки.

Температура модели установлена в 0.1, потому что здесь важнее воспроизводимость и точность, чем креативность.

SEO заголовок ограничивается 70 символами. SEO описание проверяется на длину от 800 до 1200 символов. Валидация отдельно проверяет, что значения характеристик встречаются во входных specs.

## Ограничения и дальнейшие улучшения

Проверка отсутствия галлюцинаций по строкам не заменяет полноценный evaluation набор. Для production я бы собрал 50 или 100 размеченных заявок, добавил тесты на извлечение чисел и единиц, проверку изменения единиц измерения и ручное подтверждение карточки при низкой уверенности.

Для изображений потребуется vision модель и отдельные тесты качества OCR. Для сложных паспортов можно добавить предварительное извлечение текста, словарь единиц и нормализацию обозначений, не изменяя исходное значение без записи в assumptions.

В проекте нет базы данных, CMS и деплоя, потому что они не требовались для MVP.
